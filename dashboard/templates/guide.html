How to Use

Reference for using the dashboard: a quick walkthrough, hardware requirements, the module types you'll encounter, and a few tips for less common situations.

1. Quick walkthrough

  1. 1

    Look at the homepage

    All 10 modules, grouped into 4 stages, plus the pipeline flow sidebar for quick navigation.

    Go to the dashboard home
  2. 2

    Open a module

    Select any card to view its description, dependency status, and Run/Launch controls.

  3. 3

    Install requirements, if needed

    If the page shows a "Missing" banner, select Install requirements. This creates a dedicated environment for the module and configures the dashboard to use it automatically.

  4. 4

    Launch or Run

    GUI modules open a native window. CLI modules provide a form and a live log.

  5. 5

    Repeat for each module needed

    Proceed through the MatchPlant pipeline from the dashboard home, in order.

    Go to the dashboard home

2. Hardware requirements

Everything runs on your own computer's hardware, not a remote server:

  • GPS embedding, GCP marking, annotation, and image splitting run fine on a normal laptop.
  • For OpenDroneMap (orthomosaic generation) and training or testing the detection model, a GPU is recommended for higher-quality results and faster processing, along with at least 16 GB of RAM. Free disk space needed depends on the size of your UAV image dataset.

3. Module types

Every module card is tagged with one of the following:

  • gui Opens a native desktop window (Tkinter) on this computer.
  • cli Runs from a form on the module's page, with output streamed to a live log.
  • config Configured by editing a YAML file on the page before running.
  • shell Runs a shell or PowerShell script rather than Python.

4. Tips

  • Dependency status. Each module page indicates whether its required packages are installed, checked automatically against that module's own requirements*.txt. If anything is missing, Install requirements creates a dedicated environment for that module and configures the dashboard to use it.
  • Live output. Launch, Run, and Install requirements all stream their output to a log panel on the page. Stop cancels an active process. Each module page also retains a short history of recent runs.
  • Source code. Each module page links to its folder, README, script, and requirements file on GitHub, so the underlying code can be reviewed before running it.
  • Pipeline order. The homepage sidebar lists all modules in pipeline order. Steps 6-1 and 6-2 are alternative paths to a trained model, training from scratch or fine-tuning a pretrained checkpoint, and both lead into step 7.
  • Custom environments. The Settings page allows a module to be pointed at an existing Python environment instead of a newly created one. This is only needed if a compatible environment (for example, an existing PyTorch or GDAL setup) already exists.
